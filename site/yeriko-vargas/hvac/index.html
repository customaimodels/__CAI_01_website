The guidelines

The rules every page is written to, word for word from the file the writer reads last. Lines marked law are checked in Python and a broken one throws the draft away. Open any rule.

1. One host, always2 checked in Python · 0 guide
  • lawThe site is https://customaimodels.com. Never write www. anywhere.
  • lawInternal links are relative: /articles/<slug>/. Never a full customaimodels.com URL in the body.
2. Answer first1 checked in Python · 1 guide
  • lawanswer: 40 to 70 words. It answers the headline's question in plain words, as if it were the only paragraph an engine lifts. No "In this article", no "we will explore". Starts with the claim.
  • guideIt must stand alone: name the subject (no "it", "this" as the first word).
3. Headings people actually ask2 checked in Python · 1 guide
  • lawAt least 2 section h2s are questions, ending in ?, phrased the way an operator would type them ("Why does RAG fail on spreadsheet data?"). The others keep his voice and one search term.
  • guideThe first 1-2 sentences under each h2 answer that heading directly. Detail comes after.
  • lawHeading ladder: the page owns the one h1 (the headline), each section owns its h2. Inside a section's html only h3, then h4 under it -- never h1/h2, never a skipped level.
4. Quotable passages0 checked in Python · 4 guide
  • guideEach section has at least one paragraph of 40 to 120 words that makes sense with no context around it.
  • guideName things: tools, file types, steps, failure modes. Specific beats clever.
  • guideUse a <ul> list where the content is a list (steps, failure points, checks). At least one per article.
  • guideNumbers ONLY from the angle or the brand brief. Never invent one. No number is better than a fake one.
4b. Chunks an engine lifts whole4 checked in Python · 2 guide
  • lawEvery section has one <p> of 40 to 120 words that answers its heading with no context around it.
  • lawNo <p> over 150 words. Engines cut long passages mid-thought; split it.
  • lawanswer is plain words a voice assistant can read aloud: no tags, no links, and it starts with the subject ("Custom AI Models…", "RAG on spreadsheets…"), never "It", "This", "We".
  • lawEvery number (over 12, or any %, $ or decimal) must appear in this brief or the angle. No source, no number.
  • guideComparisons go in a <table> with <th> headers. Definitions go in a <dl> (<dt> term, <dd> meaning). Steps in order go in an <ol>. Engines quote these structures whole.
  • guideInformation gain: lead each section with what only this angle knows (his build, his failure, his number from the brief). If a paragraph could sit on any other site, cut it.
5. Questions people ask1 checked in Python · 1 guide
  • lawfaq: 3 to 5 items, each {"q": "...?", "a": "..."}. Each a is 30 to 80 words, answers the question on its own, and adds something the sections did not say word for word.
  • guideQuestions a founder or ops lead would ask next (cost, time, data needed, what breaks, who owns it).
6. Entities0 checked in Python · 2 guide
  • guideSay "Custom AI Models" in full at least once in the body (not only in the footer).
  • guideYeriko Vargas is the author. Detroit / Oakland County only when the angle is about a place.
7. Never0 checked in Python · 2 guide
  • guideNo hype words (the banned list), no em dashes, no invented clients, results, quotes or awards.
  • guideNo text hidden from people that only bots see. What the schema says, the page shows.
Voice4 checked in Python · 0 guide
  • lawNo machine phrases: moreover, furthermore, in conclusion, testament to, it's important to note, pivotal, navigate the, landscape of, dive into, cutting-edge, when it comes to, in this article (full list in 02_voice.py). Say it the way an engineer says it out loud.
  • lawRhythm: mix 4-word punches with 25-word sentences. A body where every sentence is the same length fails.
  • lawNo word opens more than 30% of the sentences.
  • lawAt most 2 "not X, it's Y" lines in the whole piece. State the point once.
